        Review check
        ① What is the difference between the schema rejecting input and the tool executor throwing? ② What does thread_id solve, and what does revision solve? ③ Why does the process returning after an interrupt not mean the flow is finished? ④ Why does the model propose a call while the code actually executes it?
        Check your answers
        The schema checks arguments before execution; an executor error comes from the business logic or the data source. thread_id locates the checkpoint; revision prevents approving a stale draft. An interrupt stores a task to resume, continued by Command(resume). The model only produces a structured intent; the code validates arguments, enforces permissions, and executes the tool.
